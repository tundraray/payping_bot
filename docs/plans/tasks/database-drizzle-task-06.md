# Task 06: Generate Initial Database Migrations

Metadata:
- Phase: Phase 3 - Database Providers
- Dependencies: Task 05 (DatabaseProvider must exist), Task 03 (schema must be defined)
- Provides: drizzle/*.sql migration files
- Size: Small (generated files, no implementation)

## Implementation Content

Generate SQL migration files from TypeScript schema definitions using drizzle-kit. These migrations will be applied programmatically on application startup by DatabaseProvider.

**Migration generation workflow**:
1. Run drizzle-kit generate command
2. Review generated SQL for correctness
3. Commit migration files to repository

## Target Files
- [ ] drizzle/0000_initial_schema.sql (generated by drizzle-kit)
- [ ] drizzle/meta/_journal.json (generated by drizzle-kit)
- [ ] drizzle/meta/0000_snapshot.json (generated by drizzle-kit)

## Implementation Steps

### 1. Verify Prerequisites
- [ ] Verify drizzle.config.ts exists (from Task 02)
- [ ] Verify schema files exist in libs/db/src/schema/ (from Task 03)
- [ ] Verify DATABASE_URL is set in environment (can use placeholder for generation)

### 2. Generate Migrations
- [ ] Run: `npx drizzle-kit generate`
- [ ] Verify drizzle/ directory is created at project root
- [ ] Verify migration SQL file(s) created in drizzle/
- [ ] Verify meta files created in drizzle/meta/

### 3. Review Generated SQL (AC-1.1 through AC-1.5)
- [ ] Open generated SQL file(s)
- [ ] Verify CREATE TABLE statements for all 4 tables:
  - transactions table with hash unique index
  - users table with telegram_id unique constraint
  - subscriptions table with foreign key to users
  - payments table with foreign key to users
- [ ] Verify all tables use GENERATED ALWAYS AS IDENTITY for primary keys (AC-1.5)
- [ ] Verify indexes created:
  - idx_transactions_timestamp
  - idx_subscriptions_user_id
  - idx_subscriptions_expires_at
  - idx_payments_user_id
- [ ] Verify foreign key constraints have ON DELETE CASCADE
- [ ] Reference Design Doc contract definitions section

### 4. Validate Migration Syntax
- [ ] Check for any SQL syntax errors
- [ ] Verify column types match schema definitions
- [ ] Verify constraints are properly defined
- [ ] If issues found: Fix schema in Task 03 files, regenerate migrations

### 5. Commit Migration Files
- [ ] Ensure drizzle/ directory is not in .gitignore
- [ ] Stage migration files for commit
- [ ] Note: Migration will be applied in Phase 5 when DbModule wires providers

## Completion Criteria
- [ ] Migration SQL files generated successfully
- [ ] All 4 tables present in migration
- [ ] All indexes and constraints defined correctly
- [ ] Identity columns used for primary keys (AC-1.5)
- [ ] Foreign keys have ON DELETE CASCADE
- [ ] SQL syntax validated
- [ ] Operation verified: L3 (Build Success) - migration files exist and are valid SQL

## Notes
- Impact scope: drizzle/ directory only, no code changes
- Constraints: Do not manually edit generated SQL unless absolutely necessary
- If schema changes are needed, modify Task 03 files and regenerate
- Migrations will be executed by DatabaseProvider.useFactory() on startup
- Migration history will be stored in database when migrations run (AC-3.3)
- This task completes the foundation layer - services can now be implemented
