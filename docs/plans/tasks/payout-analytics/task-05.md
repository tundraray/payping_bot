# Task 1.4: Generate and Apply Migration

**Status**: Not Started
**Assignee**: TBD

**Phase**: 1 - Database Schema Foundation
**Depends On**: Task 1.5 (all schemas defined)

## Overview

Generate Drizzle migration file for all new tables and indexes defined in Phase 1, review the generated SQL for correctness, and apply the migration to the development database. This task finalizes the database schema foundation required for all subsequent service implementations.

## Context

Tasks 1.1, 1.2, 1.3, and 1.5 define schemas in TypeScript. This task translates those definitions into executable SQL statements that create the actual database tables, indexes, and constraints.

**Database Changes**:
1. New table: `recipient_wallets` with classification enum
2. New table: `monthly_positions` with foreign key and unique constraint
3. New table: `salary_history` with foreign key and index
4. New index: `idx_transactions_from_address` on existing transactions table

## Target Files

### Files to Create
- `drizzle/migrations/*.sql` (generated by drizzle-kit)

## Implementation Details

### Step 1: Generate Migration

Run Drizzle Kit to generate the migration file:

```bash
pnpm drizzle-kit generate
```

**Expected Output**:
- New migration file created in `drizzle/migrations/` directory
- Filename format: `YYYYMMDD_HHMMSS_migration_name.sql`

**What Gets Generated**:
1. `CREATE TYPE` statement for `recipient_classification` enum
2. `CREATE TABLE` statement for `recipient_wallets` with all columns and constraints
3. `CREATE TABLE` statement for `monthly_positions` with foreign key and unique constraint
4. `CREATE TABLE` statement for `salary_history` with foreign key
5. `CREATE INDEX` statement for `idx_salary_history_recipient`
6. `CREATE INDEX` statement for `idx_transactions_from_address`

### Step 2: Review Generated SQL

Open the generated migration file and verify the following:

**Check 1: recipient_wallets Table**
```sql
CREATE TYPE "public"."recipient_classification" AS ENUM('UNKNOWN', 'ONE_TIME', 'EMPLOYEE', 'FREELANCER', 'FIRED');

CREATE TABLE IF NOT EXISTS "recipient_wallets" (
  "id" integer PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  "address" varchar(64) NOT NULL UNIQUE,
  "classification" "recipient_classification" DEFAULT 'UNKNOWN' NOT NULL,
  "first_seen_at" timestamp NOT NULL,
  "last_payment_at" timestamp NOT NULL,
  "total_payments" integer DEFAULT 1 NOT NULL,
  "last_amount" varchar(78),
  "hired_at" timestamp,
  "fired_at" timestamp,
  "months_without_payment" integer DEFAULT 0 NOT NULL,
  "created_at" timestamp DEFAULT now() NOT NULL,
  "updated_at" timestamp DEFAULT now() NOT NULL
);
```

**Check 2: monthly_positions Table**
```sql
CREATE TABLE IF NOT EXISTS "monthly_positions" (
  "id" integer PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  "recipient_wallet_id" integer NOT NULL REFERENCES "recipient_wallets"("id"),
  "year_month" varchar(7) NOT NULL,
  "position" integer NOT NULL,
  "transaction_hash" varchar(64) NOT NULL,
  "amount" varchar(78) NOT NULL,
  "payment_timestamp" bigint NOT NULL,
  "created_at" timestamp DEFAULT now() NOT NULL,
  "updated_at" timestamp DEFAULT now() NOT NULL,
  CONSTRAINT "unique_recipient_month" UNIQUE("recipient_wallet_id", "year_month")
);
```

**Check 3: salary_history Table**
```sql
CREATE TABLE IF NOT EXISTS "salary_history" (
  "id" integer PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  "recipient_wallet_id" integer NOT NULL REFERENCES "recipient_wallets"("id"),
  "previous_amount" varchar(78) NOT NULL,
  "new_amount" varchar(78) NOT NULL,
  "change_percent" numeric(10, 2) NOT NULL,
  "detected_at" timestamp NOT NULL,
  "transaction_hash" varchar(64) NOT NULL,
  "created_at" timestamp DEFAULT now() NOT NULL
);

CREATE INDEX IF NOT EXISTS "idx_salary_history_recipient" ON "salary_history"("recipient_wallet_id");
```

**Check 4: transactions Index**
```sql
CREATE INDEX IF NOT EXISTS "idx_transactions_from_address" ON "transactions"("from_address");
```

### Step 4: Verify Database Changes

Connect to the development database and verify:

```sql
-- Check tables exist
\dt recipient_wallets
\dt monthly_positions
\dt salary_history

-- Check enum
\dT recipient_classification

-- Check indexes
\di idx_transactions_from_address
\di idx_salary_history_recipient

-- Check foreign keys
SELECT
  tc.table_name,
  kcu.column_name,
  ccu.table_name AS foreign_table_name
FROM information_schema.table_constraints AS tc
JOIN information_schema.key_column_usage AS kcu
  ON tc.constraint_name = kcu.constraint_name
JOIN information_schema.constraint_column_usage AS ccu
  ON ccu.constraint_name = tc.constraint_name
WHERE tc.constraint_type = 'FOREIGN KEY'
  AND tc.table_name IN ('monthly_positions', 'salary_history');
```

Expected: All 3 tables exist, enum exists, 2 indexes exist, foreign keys defined correctly.
